# 📜 Instructions

## Task 1: Create a KMS Key
1. Log in to the AWS Management Console as the IAM Admin user.
2. Search for `Key Management Service` in AWS console and open it.
3. Select **Customer managed keys**, select **Create key** and configure below options:
   - key type: **symmetric**
   - key usage: **encrypt and decrypt**

4. Click **Next**.
5. Enter `nextwork-kms-key` as alias, fill in the description field and select **Next**.
6. Select your own IAM admin user as a key administrator.
7. Select **Next** and select your own IAM Admin User as a key user
8. Click **Next** & **Finish**.

## Task 2: Create and Encrypt a DynamoDB Table
9. Search for `DynamoDB` in AWS console and open it.
10. Select **Create table**.
11. Enter `nextwork-kms-table` as table name and `id` as the partition key.
12. Keep **default settings** for table settings and click **Create table**.
13. Select the created table and expand **Additional info** dropdown under **Settings** table.
14. Look for **encryption**, click on its settings and change it to **Customer managed key**. 
15. Enter the created previous KMS key and select **Save changes**.

## Task 3: Add Data to Your Table
16. Still in the created **table settings** page, expand **Actions** dropdown and click **Create item**.
17. Enter `1` for the **ID value**.
18. Click **Create item**.

## Task 4: Create a Test User
19. Search for `IAM` in AWS console and open it.
20. Navigate to **IAM users** from the left navigation pan and click **Create user**.
21. Enter `nextwork-kms-user` for **user name** and select the **Provide user access to the AWS Management Console - optional** option.
22. Select **autogenerated password** for console password and uncheck **Users must create a new password at next sign-in - Recommended**.
23. Click **Next**.
24. Select **Attach policies directly** for permissions options and add **AmazonDynamoDBFullAccess** permission policy.
25. Click **Next** and **Create user**. 
26. Select `download .csv file` to save a backup of the user's login details and leave the tab page open.

## Task 5: Validate KMS Encryption
27. Copy the `console sign in URL` value and paste it in **incognito window**.
28. Fill in the username and password (copy from the test user console sign-in details).
29. Once log in, make sure you are currently in the same region as the IAM admin user.
30. Search for `DynamoDB` in the AWS console and open it.
31. Select **explore items** and select the created table earlier but getting an **access denied** error.

## Task 6: Give Your Test User Access [Optional]
32. Using the IAM admin console login page, search for `Key Management Service` in AWS console and open it.
33. Select the created key and navigate to **key users** section.
34. Click **Add**.
35. Select the test user and click **Add**.
36. Scroll upwards to **key policy** section and click **switch to policy view**. 
37. Notice that the **allow use of the key** policy is visible there for reference.
38. Head back to the test user login session and refresh the page.
39. The DynamoDB item is accessible now.

## Task 7: Delete Resources

Delete DynamoDB table

40. In DynamoDB console, select the created table and click **Delete**.
41. Select the option to **delete all CloudWatch alarm** and leave the **backup option** uncheck.
42. Confirm the deletion.

Schedule KMS Key Deletion

43. Navigate to `KMS` console and select **Customer managed keys**. 
44. Select the created key, expand **Key actions** dropdown and  click **Schedule key deletion**.
45. Enter `7` for waiting period (days).
46. Tick the confirmation checkbox and click **Schedule deletion**.

Delete the IAM User

47. Search for `IAM` in the AWS console and open it.
48. Navigate to **IAM users** and select the created test user. 
49. Click **Delete** and confirm the deletion.
50. Delete the downloaded `.csv` file credentials from the computer as well.
